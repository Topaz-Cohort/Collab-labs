Git Workflow

Follow the Same Workflow Used by Professional Development Teams

Every contribution follows the same process—from cloning the repository to opening a Pull Request for review. Master this workflow and you'll be collaborating like a professional developer.

01

Clone Repository

Download the latest version...

git clone <repository-url>
02

Create Branch

Create your own feature branch before writing code.

git checkout -b feature/project-name
03

Build Feature

Work only on your assigned lab and commit small, meaningful changes.

04

Stage Changes

Add your modified files to the staging area.

git add .
05

Commit

Save your work with a clear and meaningful commit message.

git commit -m "feat: ..."
06

Push Branch

Upload your feature branch to GitHub.

git push origin feature/project-name
07

Open Pull Request

Request that your feature branch be reviewed before it is merged into the main branch.

08

Code Review

Receive feedback, make improvements, and update your Pull Request when necessary.

09

Merge to Main

After approval, your Pull Request is merged into the main branch.

Remember Before Every Coding Session

  • Switch to the main branch.
  • Pull the latest changes from GitHub.
  • Switch back to your feature branch.
  • Start building your assigned feature.
  • Commit often with meaningful messages.
  • Push your branch regularly.
  • Open or update your Pull Request.

Frequently Asked Questions

Questions New Developers Usually Ask

Here are answers to some common questions about collaborating on this project using Git and GitHub.

Why can't I push directly to the main branch?

The main branch is protected. Every change must go through a Pull Request so it can be reviewed before being merged.

What should I do before I start coding?

Checkout the main branch, pull the latest changes, then switch back to your feature branch before writing any code.

What happens if my Pull Request needs changes?

Stay on your feature branch, make the requested changes, commit them, and push again. Your Pull Request will update automatically.

Can I edit another developer's project?

No. Only work on the files assigned to you unless your instructor asks you to collaborate on another feature.
